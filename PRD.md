# Product Requirements Document (PRD)

## Project: Antigravity Workflow Playground

---

## 1. Document Overview
This document defines the goals, functional requirements, technical stack, and development milestones for the **Antigravity Workflow Playground**. This application serves as a learning environment and interactive demonstration tool for developers to understand the Get Shit Done (GSD) context engineering workflow.

---

## 2. Product Goals & Vision
AI coding assistants suffer from "context rot" as chat histories bloat, leading to performance decay and higher costs. The Antigravity Workflow Playground is designed to:
* **Educate**: Visually illustrate the 5-phase GSD lifecycle (`Init` ➔ `Discuss` ➔ `Plan` ➔ `Execute` ➔ `Verify`).
* **Demonstrate Context Management**: Show how compressing context and externalizing state preserves model latency, accuracy, and budget.
* **Provide interactive feedback**: Allow developers to manually trigger stages, run automated execution loops, and inspect code diffs generated by a simulated agent.

---

## 3. Target Audience & Use Cases
* **Orchestrators & Developers**: Looking to learn how agentic coding environments manage files, test, and commit autonomously.
* **Teams Evaluating Agents**: Demonstrating why GSD prevents token-limit crash scenarios.

---

## 4. Functional Requirements

### 4.1 Stepper Simulator (`simulator-panel`)
* **Interactive Timeline**: A visual horizontal bar mapping 5 phases: `Init`, `Discuss`, `Plan`, `Execute`, `Verify`.
* **Manual Triggering**: Clicking a phase node launches localized, simulated logs specific to that phase.
* **Autonomous Cycle**: A "Run Full GSD Cycle" button walks through all phases with automated timers, printing live streams to the console.
* **Terminal output**: Black-box console window styling supporting syntax-colored log prefixes (`[INFO]`, `[TOOL]`, `[SUCCESS]`, `[COMMIT]`, `[SYSTEM]`).

### 4.2 Context Window Gauge (`context-gauge`)
* **Radial Representation**: A circular SVG meter indicating active tokens (up to 200,000 max).
* **Color Thresholds**: 
  * `Healthy`: < 70,000 tokens (Green)
  * `Warning`: 70,000 - 140,000 tokens (Orange)
  * `Danger / Context Rot`: > 140,000 tokens (Red)
* **Compression Control**: A "Prune Context" action button simulating context summarizing. It must show loading indicators during a 15-second process, then reset active tokens back down to 25,000, updating the cost/token savings counters.

### 4.3 Task Kanban Board (`kanban-board`)
* **Three Columns**: `To Do`, `In Progress`, `Done`.
* **Automated Task Resolution**: A "Let Agent Resolve" action button. Once clicked, the task moves to `In Progress`, prints execution logs, runs mock unit tests, registers a git commit, and moves to `Done`.
* **Diff Inspector**: Clicking completed tasks triggers a modal displaying a simulated, colored git-style code diff showing what changes were made.

### 4.4 Analytics Telemetry
* **KPI Metrics**: 
  * Active state identifier.
  * Task progress fraction.
  * Commits made.
  * Estimated monetary cost saved by context optimization.
* **Token Comparison Graph**: A Recharts-powered telemetry chart comparing standard token usage (climbing indefinitely) against the pruned GSD usage.

---

## 5. Technical Requirements

* **Framework**: Next.js 16 (App Router)
* **Type System**: TypeScript
* **Styling**: Tailwind CSS v4 (configured via HSL variables for dark mode and glassmorphism)
* **Components**: ShadCN UI (using `@base-ui/react` primitives)
* **Icons**: `lucide-react`
* **Charts**: `recharts` (wrapped with client-side mounts to avoid Next SSR hydration errors)

## 6. Milestones & Phased Roadmap

### 🏁 Milestone 1: Core Framework & Design System
* **Goal**: Bootstrap Next.js, configure theme variables, and initialize ShadCN.
* **Deliverables**:
  * Next.js App Router workspace config.
  * `globals.css` with theme design tokens.
  * ShadCN Button, Card, Badge, Progress, Tooltip, and Dialog installation.
* **Status**: Complete.

### 🚀 Milestone 2: Feature Component Implementation
* **Goal**: Build isolated user interface panels.
* **Deliverables**:
  * Radial SVG token gauge.
  * Stepper timeline and log console.
  * Kanban Columns and Task Card widgets.
  * Code diff inspector modal.
* **Status**: Complete.

### 📊 Milestone 3: Telemetry & State Integration
* **Goal**: Tie components to global React states and integrate telemetry charts.
* **Deliverables**:
  * Recharts area chart plotting pruning efficiency.
  * State coordinators for automated GSD execution loops, task resolution, and token counters.
  * Production compilation verification (`npm run build`).
* **Status**: Complete.

### ⚙️ Milestone 4: Real-Workspace Sync (Future)
* **Goal**: Connect the playground to actual filesystem activities.
* **Deliverables**:
  * Read actual local git logs to populate the commit metric.
  * Watch actual workspace file changes using filesystem event listeners (`chokidar`) and print real-time workspace activity in the terminal.
* **Status**: Backlog.

### 🌐 Milestone 5: Multiplayer & Collaboration (Future)
* **Goal**: Support remote workspace sharing.
* **Deliverables**:
  * Synchronize board updates via WebSockets.
  * Authenticate multiple agent profiles.
* **Status**: Backlog.
